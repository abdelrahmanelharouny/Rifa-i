# Phase 9 Report — Control-Flow Graph Analysis

## Objective

Introduce a reusable, deterministic control-flow analysis layer over Rifa'i bytecode without changing language semantics, VM execution, or the versioned bytecode format.

## Delivered

- Added `rifai.bytecode.cfg` with immutable `BasicBlock` and `ControlFlowGraph` models.
- Split each code chunk at its entry, jump targets, and instructions immediately following conditional/unconditional branches and terminal instructions.
- Modeled unconditional jump edges, conditional target and fall-through edges, ordinary fall-through, and terminal blocks.
- Added deterministic breadth-first reachability from each chunk entry.
- Reported reachable and unreachable basic blocks and instruction totals.
- Added module-level analysis for the main chunk and all function chunks.
- Exported the CFG API from `rifai.bytecode` and the top-level `rifai` package.
- Integrated CFG summaries into `rifai inspect` under `stages.bytecode.control_flow`.
- Extended unit tests and CI smoke validation; documented the architecture and public inspection shape.

## Correctness and Compatibility

This phase is intentionally analysis-only. It does not rewrite instructions, compact code, alter jump targets, affect source locations, or modify debugger metadata. No bytecode version bump is required: existing v1-v4 modules and the v4 writer remain unchanged. CFG construction expects verified jump targets; malformed targets fail explicitly rather than being silently misclassified.

## API

```python
from rifai import Compiler, analyze_module_control_flow

compiled = Compiler().compile("print(1 + 2);")
graphs = analyze_module_control_flow(compiled.module)
print(graphs["<main>"].as_dict())
```

Or export the same information as part of the full pipeline snapshot:

```bash
rifai inspect examples/phase8_collections.rif -o phase9.inspect.json
```

## Test Coverage

The new CFG tests cover:
- basic-block boundaries and conditional branch/fall-through edges;
- unreachable code classification;
- loop/back-edge traversal without infinite traversal;
- empty chunks;
- rejection of invalid jump targets;
- main and function chunk analysis;
- deterministic JSON-friendly output.

The existing compiler inspection test now verifies that CFG data is present for main and function chunks. CI additionally checks the `rifai inspect` output contains a non-empty main CFG.

## Scope Boundaries

This phase establishes the control-flow foundation for later data-flow and optimization work. It does not claim to perform dead-code elimination or alter generated bytecode; unreachable blocks are identified and reported only.
